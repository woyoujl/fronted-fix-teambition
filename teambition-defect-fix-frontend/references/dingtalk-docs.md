# 钉钉文档 / 原型读取

缺陷单中的原型、PRD、验收说明、交互说明优先作为验收证据。  
**当前无钉钉官方 DWS**：读不到文档时按下方「需用户介入」处理，不硬猜验收标准。

## 何时读取

满足任一条件即读：

- 任务备注、自定义字段、评论、附件中出现钉钉文档 / 知识库链接
- 标题或描述写“见原型 / 见 PRD / 验收文档 / 交互稿”并给出链接
- UI/交互/文案缺陷缺少期望结果，但存在产品文档链接
- 评论中出现钉钉 AI 听记 / 会议纪要资源，且与缺陷相关

## 链接提取

1. 以 `$teambition-query-defects` 放行后的任务详情为起点。
2. 富文本备注/字段用 Teambition `RenderTaskRtfV3`（如 `rtfFields="{taskId}:note"`）渲染后再抽链。
3. 抽取域名/路径：`alidocs.dingtalk.com`、`docs.dingtalk.com`、`dingtalk.com/i/nodes/`、团队约定知识库域名。
4. 保留原始 URL，不改写参数；报告与 TB 回填必须写明已读或未读及原因。

## 读取优先级

1. **已配置的钉钉文档 MCP / 连接器**（若有）。
2. **浏览器打开文档链接**：`browser_navigate` → `browser_snapshot`；登录墙或无权限则视为读失败。
3. **钉钉听记**：仅当缺陷关联听记 `resourceId` 时，可用 `GetDingTalkAIMinutesTranscript`（不是通用文档 API）。
4. **用户粘贴正文 / 导出**（仅当用户已在会话中提供）。

禁止把 `teambition-docs`（OpenAPI 知识库）当成业务原型/PRD。

## 成功判定

同时满足才可声称“已按钉钉文档修复”：

- 打开了与缺陷相关的具体文档或章节（不是仅封面/目录）
- 提取到期望行为相关的规则、文案、交互或验收点
- 修复决策能映射回该规则

## 需用户介入（强制）

当缺陷**依赖钉钉文档**才能明确期望结果，但当前读不到（无 MCP、登录墙、无权限、链接失效、正文抽不出验收点）时：

1. **提示用户**：说明 taskId、文档 URL、读失败原因，请用户粘贴关键正文或开通权限。  
2. **跳过当前 Bug**：本单结局 = **Wait**；不改代码、不提交。  
3. **继续下一单**（批量/轮询时）。  
4. **记入待办**：`dingtalk_blocked: [{ taskId, url, reason }]`。  
5. **最终总结必须提醒**：列出全部因钉钉文档被跳过的单，请用户补证后再二次修改。

无人值守 `/loop`：同样 Wait + 记入 tick/会话总结；不要阻塞整轮。

TB 回填用暂不硬修模板，勾选「钉钉文档权限或正文」，并 @ 指定操作者。

## 其他情况

| 情况 | 动作 |
| --- | --- |
| 无文档链接 | 继续用截图 / TB 描述 / 设计稿；报告未提供文档 |
| 有文档但 TB 截图+描述已足够验收 | 可 Fix；报告注明「未读钉钉文档，以 TB 证据为准」 |
| 文档与截图冲突 | 不硬修；提示用户 → 跳过 → 总结提醒 |

缺证时走 `evidence-gate.md` 的 Wait，不编造验收标准。
