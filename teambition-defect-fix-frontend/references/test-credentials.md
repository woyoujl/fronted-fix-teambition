# 本地复现与验证账号

修前端 Bug 做浏览器复现/验证时，**经常需要登录态与测试数据**。账号密码不写进 skill，由用户在当次会话提供。

## 何时必须向用户索取

在进入复现（修复前截图）或浏览器验证前，若目标页面/接口依赖登录、角色权限或特定数据，必须先向用户确认凭据，**不要猜测或沿用未知会话**。

典型需要索取的场景：

- 路由有登录守卫 / token
- 按角色显隐的按钮、菜单、审批流
- 依赖特定商户、门店、订单、商品、会员等测试数据
- 缺陷单写明账号/环境，但未给出可用密码
- 本地环境与线上账号体系不同，需单独测试账号

仅纯静态页、无鉴权的公开页，可不索取账号，但须在报告中写明「无需登录」。

## 必须提示用户提供的信息

用简短清单一次问清（缺什么问什么，勿重复追问已给出的项）：

```text
为复现并浏览器验证该缺陷，请提供本地/测试环境信息：
1. 启动方式：安装依赖命令、启动命令、访问 URL（或指出 README 位置）
2. 测试账号：用户名/手机号/工号
3. 测试密码：（仅用于当次登录复现与验证）
4. 角色/权限：如管理员、店员、仅查看等（若影响复现）
5. 必要测试数据：如订单号、门店、可点选的前置数据；没有则说明如何造数
6. 环境备注：租户、验证码绕过方式、是否需改 hosts / .env
```

用户只给账号不给密码、或声明不能提供密码时：

- **不要**硬猜密码或使用来路不明的旧密码
- 进入 Wait：TB 回填「缺测试账号/密码，无法自动复现验证」；或在用户同意下只做静态分析 + Suggest
- 可请用户自行登录后把已登录浏览器交给 agent，或提供验证码/一次性登录链（仍不写入仓库）

## 使用与保管规则

| 允许 | 禁止 |
| --- | --- |
| 当次会话在浏览器中填写登录表单 | 写入 skill、仓库、`.env` 提交、MR、TB 评论 |
| **本机 `/loop` 启动命令**中携带测试账号/密码（仅当次轮询会话） | 把密码写进 skill 正文、git、TB、长期存档 |
| 用户配置的本机环境变量 `FRONTEND_TEST_*` | 把密码回显到最终报告、截图标注、commit message |
| 报告中写「已使用测试账号 `<username>` 验证」 | 把密码写进 replay 脚本并提交 git |
| 验证结束后可退出登录 | Cursor Automations 永久 prompt 中写密码（本仓库默认不用云端 Automations） |

无人值守轮询（**本机 `/loop` 默认**）：

| 方式 | 规则 |
| --- | --- |
| **推荐**：启动 `/loop` 时把测试账号/密码写进**当次启动命令** | 仅本次会话 tick 使用；禁止写入 skill、仓库、TB、commit |
| 备选：环境变量 `FRONTEND_TEST_*` | 变量名可写进配置，值不写进 skill |
| Cursor Automations | 本仓库默认不用；禁止在永久 prompt 写密码 |

取凭据顺序：① `/loop` 启动命令 ② `FRONTEND_TEST_*` ③ 缺失且需登录 → 该单 Wait。

```text
FRONTEND_TEST_USER: <账号>
FRONTEND_TEST_PASSWORD: <密码>
FRONTEND_TEST_BASE_URL: <可选>
FRONTEND_TEST_ROLE: <可选>
FRONTEND_START_CMD: <可选>
```

## 插入流程的位置

1. 查询门禁通过、分支确认后  
2. **证据包 / 复现前**：优先用 `/loop` 启动命令或环境变量中的测试账号；交互单修仍按上方清单索取  
3. 取得凭据后再：启动服务 → 登录 → 复现 / before 截图 → 修复 → 同账号验证 / after 截图  
4. 用户迟迟不提供 → 按 `evidence-gate.md` 走 Wait 或 Suggest，不假装已浏览器验证

## 与证据门禁的关系

- 有账号密码且能登录复现 → 才可宣称浏览器验证通过  
- 无账号且必须登录 → Wait（缺测试账号），或用户明确放弃自动验证时标注「仅代码层修改，未登录验证」且默认不以「已验证通过」口径提交
