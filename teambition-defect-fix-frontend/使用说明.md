# Teambition 前端缺陷修复 Skill — 全新电脑配置与使用说明

本文面向在**全新 Windows 电脑**上从零配置并使用 `teambition-defect-fix-frontend`（配合 `teambition-query-defects`）。  
**禁止**把 Token、密码、证书写进本文档副本、业务仓库、MR、Teambition 评论或 Automation 提示词。

---

## 1. 这个 Skill 能做什么

| 能力 | 说明 |
| --- | --- |
| 查 Bug | 经 `$teambition-query-defects` 门禁，只处理已确认的 Bug/缺陷 |
| 读证据 | TB 描述/评论/截图；钉钉文档（读不到则提示并跳过）；Lanhu 不可用则截图+TB；Figma 有链才用；YApi |
| 分诊 | Fix（可修）/ Suggest（只建议）/ Wait（缺证不硬修） |
| 修复 | 最小前端改动；留在当前工作分支 |
| 验证 | 聚焦测试 + 浏览器复现；UI 类前后截图 |
| 交付 | 验证通过后当前分支 commit（可 push）；**默认不开 MR**；验证失败**自动回滚到修改前** |
| 回填 | TB 评论：原因、改动、验证、风险、SHA；并 @ Bug 修复人（`mentionUserIds`） |
| 轮询 | **默认本机 `/loop`**；启动命令带测试账号；可直接真修 |

## 2. 全新电脑清单（开箱要装什么）

### 2.1 基础软件

- [ ] **Git**
- [ ] **Node.js**（按目标前端项目要求的大版本，建议 LTS）
- [ ] **包管理器**：pnpm / yarn / npm（与项目一致）
- [ ] **Cursor**（推荐；本说明以 Cursor 为主）
- [ ] 可选：**Codex CLI**（若团队同时用 Codex，skill 需双目录同步）
- [ ] 可选：**glab**（GitLab CLI）；没有也行，skill 可用 REST API

### 2.2 账号与权限（找管理员开通）

- [ ] Teambition：能查目标项目 Bug、能发任务评论
- [ ] GitLab：能 push 当前工作分支即可（**不必**有 merge / 开 MR 权限；仅在明确要开 MR 时才需要）
- [ ] 前端测试账号：可登录本地/测试环境（专用测试号，勿用个人生产号）
- [ ] 可选：钉钉文档 / 蓝湖 / Figma / YApi 只读权限

### 2.3 你需要向同事索取的材料

1. 本 skill 目录打包（或 Git 镜像）：`teambition-defect-fix-frontend` + `teambition-query-defects`
2. Teambition MCP 接入方式（Server URL / App 凭据配置步骤，**当面或密码器传递，勿发群**）
3. 自建 GitLab 地址（例：`http://gitlab.example.com`）与 Personal Access Token 申请方式
4. 常用前端仓库 clone 地址、默认分支（如 `develop`）、本地启动说明
5. TB 的 `projectId`（或项目名，便于首次查询）

## 3. 安装 Skill 文件

### 3.1 目标路径（两处保持一致）

```text
%USERPROFILE%\.cursor\skills\teambition-defect-fix-frontend\
%USERPROFILE%\.cursor\skills\teambition-query-defects\

%USERPROFILE%\.codex\skills\teambition-defect-fix-frontend\   （若使用 Codex）
%USERPROFILE%\.codex\skills\teambition-query-defects\
```

### 3.2 PowerShell 落盘示例

假设同事把 skill 压缩包解压到 `D:\skills-drop\`：

```powershell
$drop = 'D:\skills-drop'   # 改成你的解压目录

# Cursor（必需）
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.cursor\skills" | Out-Null
Copy-Item -Recurse -Force "$drop\teambition-defect-fix-frontend" "$env:USERPROFILE\.cursor\skills\"
Copy-Item -Recurse -Force "$drop\teambition-query-defects" "$env:USERPROFILE\.cursor\skills\"

# Codex（可选）
if (Test-Path "$env:USERPROFILE\.codex") {
  New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.codex\skills" | Out-Null
  Copy-Item -Recurse -Force "$drop\teambition-defect-fix-frontend" "$env:USERPROFILE\.codex\skills\"
  Copy-Item -Recurse -Force "$drop\teambition-query-defects" "$env:USERPROFILE\.codex\skills\"
}
```

### 3.3 确认文件在

```powershell
Get-ChildItem "$env:USERPROFILE\.cursor\skills\teambition-defect-fix-frontend"
Get-ChildItem "$env:USERPROFILE\.cursor\skills\teambition-query-defects"
# 应能看到 SKILL.md；修复 skill 还应有 references\ 与 agents\
```

**重启 Cursor**（或新开 Agent 会话），否则可能读不到新 skill。

## 4. 配置 MCP（Cursor）

打开 **Cursor Settings → MCP**，按团队文档添加并登录以下服务（名称以你司实际为准）：

| 用途 | 常见名称 | 缺了会怎样 |
| --- | --- | --- |
| TB 任务查询/评论 | `teambition` / `teambition-user` / `teambition-app` | **无法修 Bug**（查单门禁过不去） |
| TB OpenAPI 说明 | `teambition-docs` | 仅影响查 API 文档，不影响查任务 |
| YApi | `yapi_auto_mcp` 等 | 接口类缺陷少契约对照 |
| 蓝湖 | `lanhu` | UI 对照降级 |
| Figma | Framelink / figma MCP | UI 对照降级 |
| 钉钉文档 | `dingtalk-docs`（若有） | 可用浏览器打开链接兜底 |
| 浏览器 | Cursor 自带 `cursor-ide-browser` | 一般已有；用于复现与截图 |

配置后在对话里试一句：「用 Teambition 查一下当前用户」，确认 MCP 已鉴权。

## 5. 配置环境变量（GitLab + 测试账号）

在 **PowerShell（管理员非必须）** 中配置**用户级**环境变量。把尖括号换成你的真实值，**不要提交到 Git**。

### 5.1 GitLab（push 当前分支；开 MR 非默认）

```powershell
# 自建 GitLab 填实际 Host；官方云则为 https://gitlab.com
[Environment]::SetEnvironmentVariable('GITLAB_HOST', 'http://你的GitLab地址', 'User')
[Environment]::SetEnvironmentVariable('GITLAB_TOKEN', '你的PersonalAccessToken', 'User')

# 当前窗口立即生效
$env:GITLAB_HOST = [Environment]::GetEnvironmentVariable('GITLAB_HOST', 'User')
$env:GITLAB_TOKEN = [Environment]::GetEnvironmentVariable('GITLAB_TOKEN', 'User')

# 校验（不应打印 token）
Invoke-RestMethod -Headers @{ 'PRIVATE-TOKEN' = $env:GITLAB_TOKEN } `
  -Uri "$($env:GITLAB_HOST.TrimEnd('/'))/api/v4/user" |
  Select-Object username, id
```

Token 权限建议：能读写仓库、push 当前分支即可；**默认不需要**创建 MR / merge 权限。  
若 token 曾出现在聊天记录中，先到 GitLab **轮换**再写入环境变量。

### 5.2 前端测试账号（无人值守轮询推荐；人工修 Bug 也可当场输入）

```powershell
[Environment]::SetEnvironmentVariable('FRONTEND_TEST_USER', '测试账号', 'User')
[Environment]::SetEnvironmentVariable('FRONTEND_TEST_PASSWORD', '测试密码', 'User')
# 可选
[Environment]::SetEnvironmentVariable('FRONTEND_TEST_BASE_URL', 'http://localhost:5173', 'User')
[Environment]::SetEnvironmentVariable('FRONTEND_TEST_ROLE', '管理员', 'User')
```

人工修单个 Bug 时：即使未配环境变量，Agent 也会按 `test-credentials.md` **主动向你索取**启动方式与账号密码（仅当次会话使用，不会写入 TB/MR）。

### 5.3 让 Cursor 读到新变量

改完用户环境变量后：**关掉并重开 Cursor**（或注销再登录 Windows），再开 Agent。

## 7. 日常使用（有人值守）

### 7.1 推荐提示词

在 Cursor Agent 中打开目标前端仓库，发送例如：

```text
使用 $teambition-defect-fix-frontend 修复前端 Bug。
先调用 $teambition-query-defects。
项目 projectId：<PROJECT_ID>
负责人：我
状态：未完成
确认分支后再改代码。
```

或指定单号：

```text
使用 $teambition-defect-fix-frontend 处理 Teambition 任务 <TASK_ID>。
先走查询门禁，确认是前端 Bug 后再修。
```

### 7.2 Agent 会怎么走

1. 查询并核验 Bug（非确认单会停）  
2. 确认 Git 分支  
3. 需要登录时 → **提示你输入测试账号/密码/启动方式**  
4. 读钉钉/设计/YApi（能读则读）  
5. 复现 → 最小修复 → 测试 + 浏览器验证  
6. 通过则在**当前分支** commit（可 push）；**默认不开 MR**  
7. TB 回填结论；缺证则 Wait/Suggest，不硬修  

### 7.3 批量

仅当你**明确列出多个任务 ID** 时才会批量；默认同分支一 Bug 一 commit。验证失败项**必须自动回滚到修改前**，不影响已通过项。

### 7.4 自检是否配置成功

在新会话试跑：

```text
使用 $teambition-defect-fix-frontend 做一次 dry 说明：
列出本机是否读到 skill、Teambition MCP 是否可用、GITLAB_HOST 是否已配置（不要打印 token）。
再调用 $teambition-query-defects 查我名下未完成 Bug（projectId=...），只列候选，不改代码。
```

期望：能列出已确认 Bug 或明确说明缺 MCP/`projectId`。

## 8. 无人值守怎么跑

### 8.1 结论

| 方式 | 是否可无人 | 适用 |
| --- | --- | --- |
| 普通聊天修 Bug | 否 | 日常 |
| 本机 `/loop` | 半自动（Cursor 需开着） | 试跑 |
| **Cursor Automations** | 是 | 长期定时 |
| Windows 计划任务 | 是（需自建） | 高级 |

**默认不会自动跑**；必须你显式开启，并填齐 `poll_config`。

### 8.2 启用前必填

```text
projectId:
assignee: 我（或姓名）
repo_path: D:\code\xxx-frontend
base_branch: develop
mode: dry-run          # 先 dry-run，再改 fix-one
max_per_tick: 1
allow_commit: false     # dry-run 时 false；真修时 true
allow_mr: false         # 默认不开 MR
allow_tb_comment: true
empty_tick: quiet
secondary_pass: true
skip_if_dirty: true
cooldown_minutes: 120
interval: 30m
```

并确认已配置：`GITLAB_TOKEN` / `GITLAB_HOST`，以及需登录时的 `FRONTEND_TEST_USER` / `FRONTEND_TEST_PASSWORD`。

### 8.3 建议上线顺序

1. 人工成功修通 1 个 Bug（全流程）  
2. `mode: dry-run` 跑 1～2 个 tick（只查不分）  
3. `/loop` + `fix-one` 试跑  
4. 再创建 Cursor Automations 定时任务  

详细策略见 skill 内 `references/polling.md`。

## 9. 安全红线（必读）

- 禁止把 GitLab Token、TB Token、测试密码写入仓库、skill 正文、MR、TB、Automation prompt  
- 禁止自动 merge、禁止在未要求时主动开 MR、禁止 force-push 共享分支  
- 禁止证据不足时硬改业务逻辑  
- 禁止为过验证而删测试、降断言  
- Token/密码若曾粘贴到聊天：尽快在对应平台**轮换**

## 10. 常见问题

| 现象 | 处理 |
| --- | --- |
| 找不到 skill | 检查 `%USERPROFILE%\.cursor\skills\...` 是否有 `SKILL.md`，重启 Cursor |
| 查不了 TB | MCP 未配/未登录/Token 过期；先修 Teambition MCP |
| push 失败 | 检查 `GITLAB_HOST`、`GITLAB_TOKEN`、remote、当前分支 push 权限；新开终端后再开 Cursor |
| 误开了 MR | 默认策略应不开；关掉该 MR 或说明用户曾明确要求 |
| 轮询重复修同一单 | 检查冷却与「已回填 SHA」去重是否生效；看 `polling.md` |
| Cursor 读不到环境变量 | 改 User 环境变量后必须重启 Cursor |
